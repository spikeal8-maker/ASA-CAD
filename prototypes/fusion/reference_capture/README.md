# ASA-CAD: полный первичный каталог интерфейса Fusion

Цель: перестать угадывать состав вкладок, команд и меню по скриншотам. Источником является запущенный Fusion на D2-R2.

## Готовый read-only экспортёр

`ASACAD_UI_Exporter/ASACAD_UI_Exporter.py` — Python Script для официального `adsk.core` API Fusion. Скрипт только читает доступные через API рабочие пространства, вкладки, панели, команды, разделители, dropdown, split-button, состояния `isVisible`, `isEnabled`, `isPromoted`, связанные CommandDefinition (ID, имя и tooltip), а также QAT/NavToolbar. Не вызывает `execute()`, не открывает модели и не редактирует их. Иконки Autodesk не выгружает.

На D2-R2 экземпляр установлен в:

`C:\Users\spike\AppData\Roaming\Autodesk\Autodesk Fusion 360\API\Scripts\ASACAD_UI_Exporter`

Для первого запуска в открытом Fusion:
1. Нажмите `Shift+S` или выберите `Utilities → Scripts and Add-Ins`.
2. Откройте вкладку `Scripts`, выберите `ASACAD_UI_Exporter` и нажмите `Run`.
3. Если скрипта не видно, нажмите `+`, выберите `Script or add-in from device` и укажите установленную папку выше. Это не требует замены/переустановки Fusion.
4. Проверяйте появление файла `C:\Users\spike\Documents\ASA-CAD-Fusion-Captures\fusion-ui-latest.json`. Создаётся также версия с датой UTC.

Эти действия требуются именно внутри Fusion: стандартный Python и Windows UIAutomation не имеют прямого доступа к объектам Autodesk `adsk.core`. В журнал не записываются модели/эскизы, сведения аккаунта, файлы чертежей или иконки; только метаданные штатных инструментов.

Пример в официальной документации: https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/WriteUserInterfaceToFile_Sample.htm

## Что API НЕ даёт автоматически

Расположение пикселей в каждом popup, положение каждой кнопки в режиме скетча, анимации появления диалогов, кадры подсказок, реальные эффекты на геометрии. Их надо фиксировать отдельной системой сравнительных кадров и сценариями.

Фотометрия и геометрия UI: одинаковая версия Fusion; разрешение/масштаб ОС/DPR/язык; фото **до**, hover, click, открытый dropdown, nested меню, подтверждение, отмена, повторный вызов. В ASA-CAD аналогичный маршрут и снимок. Дифф + ручная оценка — обязательны.

## Контроль полноты

Источник истинны — JSON-экспорт, а не придуманные 68 кнопок v4. Каждой комбинации `workspace/tab/panel/control ID` должна соответствовать запись в карте `referenceControlId -> asaCadCommandId -> visualComponent -> handler -> screenshot -> tests`.

У каждой записи отдельные состояния:
- V0: команда обнаружена в эталоне;
- V1: самостоятельно созданная пиктограмма и геометрия совпадают по проверенным снимкам;
- V2: все состояния hover/active/disabled, split-button, tooltip, popup и keyboard parity;
- F1: команда через действующий `CadUiAction` выполняет необходимую операцию;
- F2: Undo/Redo, сохранение/открытие, сценарии ошибок, повторное выполнение и документ;
- PASS: совместная проверка V1/V2/F1/F2 и приёмка владельцем.

Любой неподключённый или непроверенный пункт — **GAP**, а не «готово». Скрытая кнопка не означает отсутствующую команду. Скрипт читает и невидимые в текущем workspace элементы. По уникальным ID проверять порядок, а не по похожим названиям.

Два отдельных направления — UI parity и функциональная parity. Реальное ядро ASA-CAD (OpenCascade, PlaneGCS, CadApplication, CadDocument) остаётся единственным. Нельзя имитировать функцию визуальной анимацией, подменять сохранение или создавать второй runtime.

Не копировать исходные SVG/ресурсы Autodesk; создавать независимые пиктограммы по эталонным изображениям с визуальной проверкой. Товарные знаки Autodesk на своей странице не отображать.

Текущий продуктовый gate (`spec/process/active-work.v1.json`): `FULL_REPOSITORY_HEALTH_AUDIT`, `productCodeStartAllowed=false`. Этот инструмент только собирает данные и хранится в `prototypes/fusion`; изменения `src/web`, ядра или `main` не предусмотрены.
