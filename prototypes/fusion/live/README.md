# ASA-CAD — Fusion Live v7

**Рабочий кандидат оболочки с существующим ядром ASA-CAD. Не полный Fusion и не принятый продуктовый релиз.**

## Запуск готового комплекта

На Windows откройте `Start.cmd` в корне комплекта. Требуется уже установленный Node.js 20 или новее. Никакая установка зависимостей при таком запуске не выполняется. Открывается `http://127.0.0.1:8094/`; сервер слушает только этот компьютер. Остановить — Ctrl+C в окне сервера.

На Linux/macOS: `sh start.sh`. При отсутствии команды открытия браузера откройте тот же адрес вручную.

Нельзя запускать рабочий кандидат двойным нажатием на `app/index.html`: WASM, загрузка модулей и необходимые COOP/COEP-заголовки обслуживаются локальным сервером. Интернет/VPN для готового комплекта не нужен; все JS/CSS/WASM находятся в `app/`. Учётная запись Autodesk не используется.

**Сохранение:** используется существующий LocalStorageCadProjectHost ASA-CAD и ключ `asa-cad-m2-shell-document`. Это локальный документ в браузере, не файл в папке и не серверная синхронизация. Сохраняйте тот же браузер, профиль и адрес с портом. Очистка данных сайта удалит такое сохранение. Не обещать много документов/экспорт, которых этот host не реализует.

## Воспроизводимая сборка из репозитория

Из корня репозитория, без замены основного установщика:

```sh
npm --prefix vendor/toubkal ci
node prototypes/fusion/live/run.cjs
node prototypes/fusion/live/serve.cjs --port 8094 --open
```

В Windows PowerShell для первой команды используйте `npm.cmd`. Это не требует изменения ExecutionPolicy.

Режим разработки отдельно от основного продукта:

```sh
node prototypes/fusion/live/run.cjs serve
```

Адрес разработки — `http://127.0.0.1:8093/`; через `ASA_FUSION_PORT` можно задать иной порт. Проверенный запускаемый комплект всегда использует 8094.

Упаковка готовой сборки без внешних библиотек:

```sh
node prototypes/fusion/live/package.cjs
```

По умолчанию результат — папка `Downloads/ASA-CAD-Fusion-Live-v7` текущего пользователя. Имеющаяся папка не перезаписывается. Параметры `--source` и `--out` позволяют выбрать уже собранный каталог и новую папку. В комплект включаются лицензии, SHA256 файлов и source HEAD. Генерируемый `dist/fusion-live` не коммитится; repository-hygiene проверяется в checkout без build-output, как и в чистом CI.

## Архитектура: именно общее ядро

`entry.tsx` рендерит неизменённый продуктовый `src/web/App.tsx`. Сборка локально подменяет только точки представления CadShellTop/Main/Bottom, оформление опорной геометрии и управление камерой. `CadApplication`, `CadDocument`, `CadUiAction`, OpenCascade, PlaneGCS, выбор топологии, Undo/Redo и host сохранения остаются существующими.

Нет второго математического движка, отдельного хранилища моделей, iframe, демонстрационного массива тел или подмены результата 3D-операций. Операции вызываются через актуальные typed actions. Элементы дерева и параметры получают текущие props того же App. ViewCube управляет той же камерой, которой отображается и выбирается B-Rep.

Основные точки:
- `liveActions.ts` — привязка доступных команд, единые enablement/disabledReason; неподдержанные native IDs не выдаются за рабочие.
- `LiveTop.tsx` — исходная структура 7 Design-вкладок/180 native IDs; отдельная лента доступных команд эскиза.
- `LiveParameters.tsx` — реальные параметры и commit/cancel существующих операций.
- `LiveOrbitControls.ts`, `ProjectionCamera.ts`, `navigation.ts`, `CubeFrame.ts` — один объект камеры, реальные матрицы проекций, снимок вида и его пользовательская система ориентации.
- `ViewCube.tsx`, `ViewCubeMenu.tsx` — 26 направлений, вращение и наблюдённая в Fusion структура меню.
- `MarkingMenu.tsx` — правый клик с 8 радиальными позициями, вторым уровнем «Эскиз» и общими действиями.

## Что выполняется и проверено

Обычный пользовательский сценарий, без подстановки документа/геометрии скрытым API:

`Новый документ → эскиз XY → прямоугольник 60×40 → выдавливание 10 → выбрать верхнюю грань → второй эскиз → окружность Ø12 → вырез через всё → выбрать ребро → скругление R1 → изменить ширину 60→80 → сохранить → открыть → изменить Ø12→Ø14`.

Проверены реальные границы B-Rep, три элемента истории, две стабильные ссылки на топологию, Undo/Redo и повторное редактирование после восстановления. В сохранённом документе нет OCC-объектов и временных индексов граней/рёбер.

Ввод мышью отдельно проверен на существующей плоскости эскиза: отрезок по двум точкам, прямоугольник по двум углам, окружность по центру и радиусу. Сохраняются настоящие сущности документа, а не нарисованные экранные линии.

На 3D-модели: колесо — масштаб; средняя кнопка — сдвиг; Shift+средняя — орбита; левая — выбор; правая — контекстное меню. Режимы панели навигации позволяют также выполнить сдвиг/орбиту/масштаб левой кнопкой.

ViewCube на 3D-модели:
- 6 граней + 12 рёбер + 8 углов проверены фактическими кликами и направлением камеры.
- Ортографическая, перспективная и смешанная проекции изменяют реальные матрицы. Исправлен переход смешанного режима с грани на угол.
- Перетаскивание куба, повороты на 90°, соседние грани, главный вид.
- Сохранение главного вида с фиксированным расстоянием восстанавливает положение, up-вектор и масштаб; «Вписать в окно» использует реальные границы модели.
- Назначение текущего вида «Спереди/Сверху», сброс, пять наблюдённых пунктов размера.
- Навигационные действия не меняют геометрию или CadDocument.

## Границы, которые нельзя скрывать

1. **Все 180 native-команд не реализованы ядром ASA-CAD.** Наличие OpenCascade не равно готовому command layer Fusion. Доступны только существующие типизированные операции. Неподдержанные пункты видны, недоступны и объясняют причину.
2. **Полная команда «Отверстие» Fusion ещё не подключена.** Исправлен её самостоятельный SVG; настоящий сквозной вырез строится окружностью + выдавливанием с вычитанием. Зенковка, резьба и прочие режимы Hole не объявлены готовыми.
3. **Эскиз пока использует исходный изолированный 2D-редактор ASA-CAD.** Ввод, ограничения и сохранение используют общую модель, но 3D-орбита/ViewCube во время редактирования эскиза ещё не интегрированы. Возврат в режим модели снова подключает настоящую камеру. Не приравнивать пройденные тесты 3D ViewCube к готовности 3D Sketch-in-Viewport.
4. История строится из настоящих sketches/features, но полный rollback/suppression и редактирование каждого типа элемента через timeline не реализованы.
5. Перерисовка Hole и интерактивный куб — проверенный прогресс, **не 100% визуальная приёмка всех значков**. В каталоге остаются семейные/приблизительные SVG. Native-artwork не извлекался.
6. Right-click открывает настоящее рабочее меню; native жесты с удержанием правой кнопки во всех направлениях, индивидуальная настройка автоматического размера куба и анимированные переходы видов не заявлены.
7. Существующий gate `FULL_REPOSITORY_HEALTH_AUDIT` не снят. Основные `src/`, `vendor/`, normal build, schema, `main` и `integration` не менялись. Это отдельно запускаемый кандидат в prototype-ветке. Выбор трёх оболочек на основном старте ещё не включён.


**Typecheck: 8 существующих ошибок полной исходной UI-базы, 0 новых у кандидата.** Статус `NO_NEW_DIAGNOSTICS` не означает чистый полный typecheck. Исходные сообщения сохраняются в evidence, правила не ослаблены. Полная продуктовая приёмка, независимое архитектурное ревью и merge в main не выполнены.

## Сверка значков закреплённой ленты

В исходном каталоге Design — 180 native-команд и **142 размещения кнопок**, соответствующие 74 уникальным native ID. Для 17 ранее отсутствовавших на закреплённой ленте рисунков подготовлены индивидуальные авторские SVG. Проверка `node prototypes/fusion/tests/live-promoted-artwork.mjs` удостоверяет, что среди закреплённых кнопок не осталось общих заглушек. Браузерный тест `live-ribbon-browser.mjs` проверяет порядок всех 142 размещений, русские подписи, изображения и отсутствие переполнения на 2048×1137 и 1366×768.

**Индивидуальная отрисовка не равна совпадению с оригиналом.** В остальных (включая скрытые) 84 native-командах каталога ещё используются общие рисунки. У 28 команд — приближённая иконка семейства, 34 перерисованы, 17 ждут сверки и 17 получили новые SVG для закреплённой ленты. Нет статуса `100% визуальное совпадение` без покомандной приёмки всех состояний.


## v7 — базовая команда «Отверстие», связанная с общим ядром

Новая кнопка `FusionHoleCommand` в **Создать → Отверстие**, строке поиска, радиальном меню и клавиша **H** ведут к одному пошаговому мастеру. Операция **не имитируется декоративным телом**: мастер вызывает поочерёдно только реальные `CadUiAction` уже существующего приложения:

`part.sketch.create → sketch.circle → sketch.finish → part.cutExtrude`.

Пользователь явно выбирает грань/плоскость, задаёт центр и диаметр окружности, подтверждает эскиз и сквозной вырез. Никаких скрытых изменений документа по нажатию «Отверстие» и никакого отдельного solver. Вспомогательное состояние мастера эфемерно и не сериализуется в CadDocument. Закрытие мастера не удаляет ранее подтверждённые операции. На пустой детали кнопка недоступна с конкретной причиной. Контекстная доступность **пока ограничена случаем существующего тела непосредственно после выдавливания**: в текущем CadUiAction catalog сквозной вырез не доступен после произвольной истории.

Положительный сквозной тест `live-hole-wizard-browser.mjs`: базовая деталь 60×40×10, отмена без изменений, вход через H/поиск/правый клик/основное меню, выбор грани, попытка отрицательного диаметра (ОК запрещена), Ø12, подтверждение, реальный `cut-extrude`, 1 StableRef, сохранение, открытие. Ни один шаг геометрии не исполняется без реального UI-подтверждения.

**Функциональный статус: BASIC_THROUGH_HOLE_IMPLEMENTED, NATIVE_FUSION_HOLE_PARITY_NOT_ACHIEVED.** Глухие отверстия, посадочные элементы, резьба, зенковка, диаметр с сохранённым расположением в виде самостоятельной операции Hole и другие варианты original Fusion пока отсутствуют. Сама команда реализована как существующие Sketch+Cut-фичи в общей истории, а не как новый `feature.hole` в CAD-контрактах. Это ограничение нельзя скрывать и нельзя снимать без явного изменения ядра с независимой приёмкой.
